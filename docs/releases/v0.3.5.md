# Brimline 0.3.5

Brimline 0.3.5 is a security release. Nothing new to see in the app: what the commands and the MCP server say about an account is now filtered, `SECURITY.md` says exactly what goes out, and the public texts and the CI no longer describe the machine of the maintainer.

## What is new

- **What agents and the terminal read about an account is filtered.** The organization, the plan name, the address and the label of an account used to be passed on as they were written in `.claude.json` and in the settings. They now go through one filter: letters of any alphabet, digits and a few signs, 64 characters at most, with control and format characters (line breaks, escape sequences, right to left and zero width characters) refused. Anything else is `null`, never shortened, and an address must be a plain one. An organization or plan name that uses a sign outside that list is therefore no longer shown in the app either.
- **The filter applies on the way in and on the way out.** It runs when `.claude.json` is read and when an answer leaves (`list_accounts`, `get_usage`, `best_account`, `brimline accounts`, `brimline accounts --json`, `brimline status`, `brimline status --json`), so a `usage.json` written by an older version cannot get around it. `id` and `folder` stay absolute: `id` is the key of your settings and `folder` is the folder to give `CLAUDE_CONFIG_DIR`.
- **`SECURITY.md` says what goes out.** It no longer says that the server and the command "expose usage numbers only": it lists what is given out for each account, and says that `id` and `folder` carry the name of your macOS account.

## Good to know

- The CI runs only on the runners hosted by GitHub, every action is pinned by a full commit SHA, and `scripts/check_text.py` refuses a workflow that does otherwise, or that it cannot check. It needs PyYAML (see [CONTRIBUTING.md](../../CONTRIBUTING.md)). This changes nothing for people who install or run Brimline.
- The audit report, the notes of 0.1.0 and 0.3.4 and a few comments no longer describe the machine of the maintainer; they say the current state.
- The app, its settings and its signing are those of 0.3.4, so an update from 0.3.4 keeps the Accessibility permission.
