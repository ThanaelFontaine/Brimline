# Brimline 0.3.6

Brimline 0.3.6 is a release of fixes, two security hardenings and finishing touches. Nothing new to see in the app: one sentence is corrected on the Gemini card, a Grok sign-in with an unreadable expiry date sends nothing, and what Brimline promised about addresses and the "Do not read" choice is now held by the code itself.

## What is new

- **The Gemini card without Antigravity points to Antigravity, not to Gemini CLI.** The sentence used to end with "and in Gemini CLI (/stats model)", but Google no longer serves individual Google AI Pro and Ultra plans in Gemini CLI since 18 June 2026. It now says "They are in the Gemini app (Settings, Usage limits) and in Antigravity (/usage).", in English and in French. Nothing new is read or launched.
- **A Grok sign-in whose expiry date cannot be read no longer lets the token go.** When `expires_at` was there but in a form Brimline did not read (a named time zone, another precision), the date was ignored and the session token was sent as if it did not expire. Nothing is sent now: the Grok card says the format changed.
- **The list of addresses each reader may call is held by the registry.** A reader that forgets to restrict its client can no longer send a token to an address it did not declare, and a test checks every reader of the registry.
- **A Claude folder marked "Do not read" is no longer opened** when Brimline looks for accounts. Only the existence of its path is checked, so its address, organization and plan stay the last known ones, no longer refreshed while the box is on. `SECURITY.md` and the README say it.

## Good to know

- The design board, the icon and Open Graph image renderer and `docs/why.md` (which now says what ClaudeBar does) were also updated. These are design files, tests and documentation: nothing changes in the app.
- The app, its settings and its signing are those of 0.3.5, so an update from 0.3.5 keeps the Accessibility permission.
