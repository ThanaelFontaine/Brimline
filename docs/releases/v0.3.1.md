# Brimline 0.3.1

Brimline 0.3.1 signs Brimline with its own certificate, so that the Accessibility permission (which hiding the icons needs on macOS 27) can survive an update, says so when that permission is missing, and reads Gemini again after Antigravity's update to 1.4.10.

## What is new

- **Brimline is signed with its own certificate.** Until 0.3.0, Brimline was signed ad hoc, and macOS tied the Accessibility permission to the exact build you approved: each update lost it. The release is now signed with "Brimline Code Signing", a self-signed certificate valid until 24 October 2046, so the identity macOS checks names Brimline and that certificate, not one build. Checked on 29 October 2026 on a real Mac: the permission was given once to a signed build, a second signed build was installed over it, and the permission still covered it, with no request from macOS.
- **Brimline says when it hides without the permission.** Before, once an update took the permission away, a click on the bar hid the icons from the remembered list with no word. Now the Brimline window and Settings, Menu Bar, say that the permission is missing, what that changes and how to give it back, with an **Open the Accessibility list** button, and the first click on the bar of a launch in that state opens Settings on Menu Bar.
- **Gemini is read again after Antigravity 1.4.10.** Since 29 October 2026 the Gemini card said "Antigravity was updated: update Brimline.", only because that build was not on Brimline's list of verified builds. The text of `agy --print /usage` is the same as in 1.4.8 and 1.4.9, 1.4.10 is now on the list, and a text of an unknown form is still refused.

## Good to know

- Going from 0.3.0 to 0.3.1 still takes the Accessibility permission away once, since 0.3.0 is signed ad hoc and 0.3.1 by the certificate: give it again (remove Brimline from the Accessibility list with the minus button and add it again from the Applications folder, or turn it on if macOS asks). After that, an update keeps it.
- The certificate is self-signed: it is not an Apple Developer identity, and Brimline is still not notarized by Apple. Gatekeeper behaves as before: a disk image downloaded in a browser needs **Open Anyway** once, in System Settings, Privacy & Security ([Apple's page](https://support.apple.com/en-us/102445)). A fork, or a build from the source, stays signed ad hoc.
- The allow-list of the menu bar is still a private API of macOS that Apple does not document. See [docs/menu-bar.md](../menu-bar.md).
