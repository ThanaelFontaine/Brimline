# Brimline 0.3.3

Brimline 0.3.3 fixes Gemini. Antigravity updates itself every few days, and each new build turned the Gemini card into "Antigravity was updated: update Brimline." although nothing had changed in what `agy` prints. From this version, a new build of Antigravity is read with nothing to add to Brimline.

## What is new

- **Gemini no longer breaks at each update of Antigravity.** Antigravity updated itself four times in a few days (1.4.8, 1.4.9, 1.4.10 and 1.4.11) and Brimline kept a list of the builds it had checked, so every new build was refused until a new Brimline came out. Brimline now trusts a rule instead of a list: the program at `~/.local/bin/agy` must carry the Developer ID signature of Google (team `EQHXZ8M8AV`, identifier `cli`), checked by macOS before each launch. A build signed by Google is read like the one before it. A program that is not signed by Google is not launched. If `agy` is being replaced while it is checked, Brimline looks once more after 2 seconds, in the same read. Checked on 4 November 2026: `agy --print /usage` printed the same five lines on 1.4.11 as before.
- **The card says what really happened.** "Google changed the /usage report: update Brimline." now means only that the report changed. A program that does not carry Google's signature is `unavailable`, with the reason `signature_not_recognized` (in the app, in `brimline status` and in the JSON for agents) and the sentence "Brimline does not recognize Google's signature on agy (~/.local/bin/agy), so it does not launch it."
- **`agy --version` is no longer launched.** Nothing depends on its text any more, so Brimline starts `agy` once per read instead of twice.

## Good to know

- What is not checked is written in [SECURITY.md](../../SECURITY.md): the signature is checked just before the launch (closing that window is the next lot), `notarized` and online revocation are not part of the rule, and what `agy` launches itself is not checked. An `agy` installed elsewhere than `~/.local/bin/agy` (Homebrew, a link) is still not launched.
- The disk image is built with Pillow 13.0.0 (was 12.0.0), which fixes the security advisories published against Pillow 12.x. Pillow only draws the image background at build time and never opens a file from a third party, so nothing changes for users.
- The app, its settings and its signing are those of 0.3.2, so an update from 0.3.2 keeps the Accessibility permission.

## Install

See [docs/install.md](../install.md). The one-line installer, run again, updates Brimline.
