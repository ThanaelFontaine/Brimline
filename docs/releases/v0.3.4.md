# Brimline 0.3.4

Brimline 0.3.4 makes the check of Google's signature on `agy` stronger. In 0.3.3, Brimline checked the file and then started it by its path, and a file replaced in between would have been started. From this version, the program that runs is the one that was checked. Nothing changes in what the app shows.

## What is new

- **`agy` is checked on the running process, before it runs a single instruction.** Brimline starts `agy` suspended (`posix_spawn`), asks macOS for the code of that very process (by its audit token) and checks the same Google requirement on it (team `EQHXZ8M8AV`, identifier `cli`); only then does it let it run. Any other program is killed before it ran, and the card says "Brimline does not recognize Google's signature on agy (~/.local/bin/agy), so it does not launch it." (never "Google changed the /usage report").
- **No process and no zombie is left behind.** The launcher puts `agy` in a process group of its own and stops the whole group when the run ends.

## Good to know

- The programs `agy` starts itself are still not checked. This is written in [SECURITY.md](../../SECURITY.md), with the other limits of the rule.
- Checked on the Mac mini with the real `agy` 1.4.12 started suspended: Gemini, ChatGPT and Claude are read for real, and no `agy` process is left.
- The app, its settings and its signing are those of 0.3.3, so an update from 0.3.3 keeps the Accessibility permission.
