# Providers

What Brimline reads for each provider, where the source comes from, and what it says when there is nothing it can read. Claude is on by default; every other provider is **off until you turn it on** (Settings, Accounts, or `brimline providers enable <name>`).

**Documented** means described by the provider's official documentation (with a link). **Not documented** means seen in the code of the provider's own client: it can change without notice.

## Claude

Read from the Claude Code sign-in in the macOS Keychain, with one request to `https://api.anthropic.com/api/oauth/usage` (not documented by Anthropic). See [Linking your accounts](accounts.md) and [SECURITY.md](../SECURITY.md).

## ChatGPT, through Codex

- **What Brimline reads.** Codex's own sign-in file, `~/.codex/auth.json` (Codex keeps it there, in plain text, by default: [OpenAI's authentication page](https://learn.chatgpt.com/docs/auth)), and nothing else of Codex: no `config.toml`, no Keychain item, and no program is launched. Of that file only three fields are decoded: `auth_mode`, `tokens.access_token` and `tokens.account_id`. The refresh token, the id token and an API key in the same file are never decoded. A Codex folder somewhere else (`CODEX_HOME`) is added by hand, never read from the environment: for now by writing it in `settings.json` (`extraCodexFolders`), the Settings window will get a button with the interface lot.
- **The one request.** `GET https://chatgpt.com/backend-api/wham/usage` with the access token (`Authorization: Bearer`) and the account id (`ChatGPT-Account-Id`), the call Codex itself makes for its limits. **Not documented** by OpenAI: Codex's public code is the source ([openai/codex](https://github.com/openai/codex), commit `aeb6b22c8bda5f4d4b6ab80ebd3ccdb3f47fb3ab`: `codex-rs/backend-client/src/client/rate_limit_resets.rs` for the call, `codex-rs/codex-backend-openapi-models/src/models/` for the answer, `codex-rs/login/src/auth/storage.rs` and `token_data.rs` for the file). The same limits are **documented** on OpenAI's side, but only through `codex app-server` (`account/rateLimits/read`, [documentation](https://learn.chatgpt.com/docs/app-server)) and `/status` in Codex ([documentation](https://learn.chatgpt.com/docs/pricing)): they are what to compare Brimline with, not what Brimline calls, because `app-server` is a program that renews and rewrites Codex's sign-in, and its page does not allow it for a commercial service.
- **What you see.** A window is named by its length: 18000 seconds is the 5 hour session, 604800 the week, anything else a period with its length (a free plan was seen with 30 days). A plan with no 5 hour window (OpenAI documents that Pro has none) shows the week only. Limits of one model or feature (`additional_rate_limits`) show as that model's limits, with the window length in the name when it is not a week. Each has its percentage and its reset time. Credits and spend controls in the answer are ignored.
- **Never.** An expired access token (read from the `exp` of the token, without checking its signature, with a 60 second margin) is never sent and never renewed: Codex renews it itself when it runs, so a Codex left closed for a long time shows "Open Codex to refresh the sign-in." / "Ouvrez Codex pour rafraîchir la connexion." The card is named after its folder: the address and the plan from the answer are not kept.
- **When there is nothing to read** (`not_readable`, in the app, in `brimline status` and in the JSON for agents):
  - Codex is signed in with an API key (`auth_mode` is `apikey`), reason `api_key`: "Codex is signed in with an API key: there is no subscription limit to show." / "Codex est connecté par une clé d'API : il n'a pas de limite d'abonnement à montrer."
  - `~/.codex` has no `auth.json` (Codex keeps its sign-in in the Keychain, or is signed out), reason `keychain_or_signed_out`: "Codex keeps its sign-in in the Keychain or is signed out: Brimline only reads ~/.codex/auth.json." / "Codex range sa connexion dans le Trousseau ou n'est pas connecté : Brimline ne lit que ~/.codex/auth.json." Brimline never reads a Keychain item of Codex.
  - The limits of ChatGPT conversations outside Codex have no source: OpenAI does not publish them in a readable form.
- **Other states.** The sign-in file cut short (Codex is rewriting it) is a passing failure that Brimline tries again, never "signed out"; a link, a file of someone else or one larger than 1 MiB is refused; a 401 asks to sign in again; a 429 waits as long as the provider asks, one hour at most; an answer that is not the expected one (another JSON, a page) is "format changed", never a number.
- **State of the check.** The reader is written and tested on data built from the public code of Codex CLI (the values are invented, the shape is from the source), **not yet tried on a real account**: no ChatGPT account is connected to the test Mac yet. The test data are rewritten from the skeleton of a real answer (`brimline status --live --shape --provider chatgpt`) at the real try, and this section is updated then. Until that try, ChatGPT is not "read and checked".

## Gemini: a sentence only

- **What Brimline does.** It looks only for the folder `~/.gemini` (Gemini CLI's folder) and checks that it exists and is a folder. When it does, Gemini shows one card with the sentence below. Nothing inside the folder is opened or listed, nothing is read from the Keychain, no request is made and no program is launched. When Gemini is off (the default), the folder is not even looked for.
- **Why nothing is read.** Google publishes no limit of a Gemini subscription in a form an app like Brimline can read. The call Gemini CLI itself makes (`v1internal:retrieveUserQuota`, not documented) appears, as far as Gemini CLI's code shows, to serve only Code Assist Standard and Enterprise, and since 18 June 2026 "Login with Google" in Gemini CLI is no longer possible for individual, Google AI Pro and Google AI Ultra plans ([Google's notice](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals)). The Gemini app shows its own limits, which repeat every 5 hours up to a weekly limit ([Google's help page](https://support.google.com/gemini/answer/16275805)); the only known way to read them from outside is with browser cookies, which Brimline never reads.
- **The sentence** (`not_readable`, reason `consumer_plan`, in the app, in `brimline status` and in the JSON for agents):
  - English: "Google does not publish Gemini limits in a form Brimline can read. They are in the Gemini app (Settings, Usage limits) and in Gemini CLI (/stats model)."
  - French: "Google ne publie pas les limites de Gemini sous une forme que Brimline peut lire. Elles sont dans l'app Gemini (Réglages, Limites d'utilisation) et dans Gemini CLI (/stats model)."
- **What you see.** No percentage and no reset time, never an invented number. The account is never offered by `best_account`.
- **Checked** on 27 October 2026 against the sources linked above.
